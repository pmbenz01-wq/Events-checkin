1 · ภาพรวมสถาปัตยกรรม

ระบบทำงานออนไลน์ 100% โดยใช้ Google Sheet เป็นฐานข้อมูลเดียว และ Apps Script (Web App) เป็น API ชั้นเดียวที่ทุกหน้าเรียกใช้ ห้ามให้หน้าเว็บเขียนชีตตรง เพื่อให้การล็อกและการตรวจสิทธิ์อยู่ที่จุดเดียว

FLOW
หน้าลูกค้า (public) ──POST /register──▶ Apps Script ──▶ Sheet: Registrations
                                         └──▶ ส่งอีเมล QR (MailApp)
หน้า Staff (ต้อง login) ──POST /checkin──▶ LockService ──▶ Sheet: Checkins + Registrations
  • Deploy เป็น Web App สองตัว: public (Execute as: me / Access: anyone) สำหรับลงทะเบียน และ staff (Access: anyone with Google account) สำหรับงานเจ้าหน้าที่
  • หน้าเว็บทั้งสองฝั่งเป็นไฟล์เดียวกันไม่ได้ — แยก URL/โฮสต์ เพื่อไม่ให้โค้ดฝั่ง staff หลุดถึงลูกค้า
  • ทุก response เป็น JSON รูปแบบ { ok, data, error }

3 · คอลัมน์สำคัญ

ฟิลด์ที่ผู้จัดงานเพิ่มเองผ่านหน้า “ฟิลด์ฟอร์ม” ไม่ต้องเพิ่มคอลัมน์ใหม่ทุกครั้ง — เก็บรวมใน answers_json แล้วมีคอลัมน์ช่วยอ่าน (flatten) ให้เฉพาะฟิลด์ที่ใช้ค้นหาบ่อย

Registrations ความหมาย
reg_id · event_idรหัสแถวและงานที่สังกัด
badge_codeรหัสบัตรที่พิมพ์บนบัตรและอยู่ใน QR เช่น TT26-4F2A-901
qr_tokentoken ลงลายเซ็น ใช้ยืนยันว่า QR ออกโดยระบบ
full_name · email · phoneฟิลด์หลัก 3 ตัวที่ทุกงานมี ใช้ค้นหาหน้างาน
answers_jsonคำตอบฟิลด์ที่ผู้จัดงานเพิ่มเอง (JSON)
sourceonline · walkin
statusregistered · checked_in · cancelled · deleted
checked_in_atเวลาเข้างานครั้งแรก (ISO 8601 + timezone)
checked_in_byอีเมล Google ของเจ้าหน้าที่ที่สแกน — บังคับมีค่าเมื่อ status = checked_in

ชีต Checkins เก็บทุกครั้งที่สแกน ไม่ทับของเดิม: scan_id, event_id, reg_id, badge_code, scanned_at, scanned_by, gate, device_id, result โดย result = ok · duplicate · not_found · wrong_event ทำให้ย้อนดูได้ว่าใครสแกนอะไรตอนไหน และดูสถิติแยกเจ้าหน้าที่ได้ตรงจากชีตนี้

5 · เจ้าหน้าที่หลายคนพร้อมกัน

ปัญหาที่ต้องกันคือสองเครื่องสแกนคนเดียวกันในเวลาเกือบพร้อมกัน และการเขียนชีตทับกัน แก้ด้วยสามอย่าง: ล็อกทั้งสคริปต์ตอนเขียน, ตัดสินผลจากค่าที่อ่านหลังได้ล็อกเท่านั้น, และไม่ลบทับประวัติ

function checkin(p) {
  const staff = requireStaff(p.eventId);            // ตรวจ Session.getActiveUser() กับชีต Staff
  if (!verifyToken(p.qrToken)) return err('not_found');

  const lock = LockService.getScriptLock();
  if (!lock.tryLock(15000)) return err('busy');     // คิวสั้น ๆ ไม่ให้เขียนพร้อมกัน
  try {
    const row = findRegRow(p.eventId, p.badgeCode); // อ่านสด "หลัง" ได้ล็อกแล้วเท่านั้น
    if (!row) return err('not_found');

    const already = row.status === 'checked_in';
    appendCheckin({                                  // ประวัติเขียนทุกครั้ง ไม่ทับ
      regId: row.reg_id, badgeCode: p.badgeCode,
      scannedBy: staff.email, gate: staff.gate,
      deviceId: p.deviceId, result: already ? 'duplicate' : 'ok'
    });

    if (already) {
      bumpScanCount(row);
      return ok({ result: 'duplicate', name: row.full_name,
                  by: row.checked_in_by, at: row.checked_in_at, gate: row.gate });
    }
    setRow(row, { status: 'checked_in', checked_in_at: nowIso(),
                  checked_in_by: staff.email, gate: staff.gate,
                  device_id: p.deviceId, scan_count: 1 });
    return ok({ result: 'ok', name: row.full_name, badge: buildBadge(row) });
  } finally {
    lock.releaseLock();
  }
}
  • คนแรกชนะ — checked_in_by เก็บคนที่สแกนสำเร็จครั้งแรก คนที่สแกนทีหลังได้ผล duplicate พร้อมชื่อคนแรกและเวลา (ตรงกับกล่องเตือนสีแดงในหน้า Staff)
  • ทุกการสแกนถูกบันทึก — แม้เป็น duplicate ก็ยังลงชีต Checkins ทำให้รู้ว่าใครสแกนซ้ำที่ประตูไหน
  • อ่านหลังล็อกเสมอ — ห้ามใช้ค่าที่ฝั่งเบราว์เซอร์ถืออยู่มาตัดสิน มิฉะนั้นสองเครื่องจะเห็นสถานะเก่าเหมือนกันทั้งคู่
  • เขียนแบบ batch — ใช้ setValues() ครั้งเดียวต่อการเรียก และเลี่ยงสูตรในคอลัมน์ที่เขียนบ่อย เพื่อไม่ให้ชีตคำนวณใหม่ทั้งไฟล์
  • idempotency — ให้เครื่องสแกนส่ง client_scan_id (uuid) มาด้วย ถ้าซ้ำให้คืนผลเดิมโดยไม่เขียนใหม่ กันกรณีเน็ตหลุดแล้วกดซ้ำ
อัปเดตแบบเรียลไทม์: Apps Script ไม่มี push — ให้หน้า Staff เรียก getDashboard ทุก 8–10 วินาที ส่ง since เป็นเวลาที่ได้ข้อมูลล่าสุด แล้วรับเฉพาะรายการใหม่ (เท่ากับพฤติกรรมกิจกรรมสดใน prototype) ระวังโควตา Apps Script: 20 เครื่อง × ทุก 10 วิ ≈ 7,200 เรียก/ชม.

6 · QR และความปลอดภัย

QR บรรจุข้อความสั้น ไม่ใส่ข้อมูลส่วนบุคคล: EVENT|BADGE_CODE|SIG โดย SIG คือ 10 ตัวแรกของ HMAC-SHA256 ของสองส่วนแรกด้วยคีย์ลับที่เก็บใน Script Properties ทำให้ปลอมบัตรไม่ได้ และถ้าใครถ่ายรูป QR ต่อกันก็ยังกันซ้ำได้ด้วย duplicate detection

  • สร้างภาพ QR ฝั่งเบราว์เซอร์ด้วยไลบรารีในหน้าเว็บ ไม่ต้องพึ่งบริการภาพภายนอก (ข้อมูลไม่ออกนอกระบบ)
  • ลิงก์เปิดดู QR ซ้ำใช้ token แยกคนละตัวกับ SIG และหมดอายุหลังงานจบ 7 วัน
  • PDPA: เก็บ consent เป็นคอลัมน์ (consent_at, เวอร์ชันนโยบาย) และตั้งรอบลบข้อมูลหลังงานตามที่แจ้งลูกค้า

7 · สิทธิ์เจ้าหน้าที่และการพิมพ์บัตร

ตรวจตัวตนจาก Session.getActiveUser().getEmail() เทียบกับชีต Staff — ห้ามส่ง role มาจากฝั่งหน้าเว็บ บทบาท: ADMIN ทำได้ทุกอย่างรวมถึงลบและตั้งค่า, STAFF สแกน เช็คอิน walk-in แก้ไข, VIEWER ดูอย่างเดียว ขอบเขตกำหนดต่อ Event ในคอลัมน์ event_scope

บัตรพิมพ์จากหน้าเว็บโดยตรง: BadgeConfig เก็บ size (A6 · 4×6in · 80mm), ธงเปิด/ปิดองค์ประกอบ (show_logo, show_org, show_type, show_qr, show_bar) และ accent หน้าเว็บ render บัตรตาม config แล้วสั่งพิมพ์ที่ขนาดกระดาษจริง — ตั้ง margin 0 และให้เครื่องพิมพ์บัตรใช้ขนาดกำหนดเอง 105×148 มม. สำหรับ A6

8 · ลำดับงานที่แนะนำ

  1. ตั้งชีตตามหัวข้อ 2–3 พร้อมข้อมูลตัวอย่าง 20 แถว
  2. Apps Script: register + getEventForm → ต่อหน้าลูกค้าให้ลงทะเบียนได้จริงและได้ QR
  3. checkin พร้อม LockService + หน้าสแกนบนมือถือ (ทดสอบสองเครื่องยิงพร้อมกันจริง)
  4. รายชื่อ ค้นหา walk-in แก้ไข ลบ + AuditLog
  5. ฟิลด์ฟอร์มต่อ Event และ BadgeConfig
  6. Dashboard + สถิติแยกเจ้าหน้าที่ และซ้อมงานจริง 1 รอบก่อนวันงาน

ข้อควรระวังก่อนวันงาน: ทดสอบโควตา Apps Script ที่จำนวนเครื่องจริง, สำรองไฟล์ชีตอัตโนมัติรายวัน, และเตรียมโหมดค้นหาด้วยชื่อไว้เสมอกรณีกล้องสแกนไม่ทำงาน
